About

I'm a software developer since 1997, working across software systems, firmware, electronics and embedded systems—primarily in agricultural and industrial automation.

My work connects C/C++, microcontrollers, real-time software and communication protocols at the hardware/software boundary. I focus on the path from what happens on the bus to what a machine does in the field.

I brought that perspective together in my technical book, Fundamentos de CAN, J1939 e ISOBUS: a practical route from the physical layer to protocol analysis and diagnosis.

03.5

Code lab

Reason about shared state

The book connects the wire, frame and systems in the field. This interactive lab explores a related embedded concern: safe ownership of shared data.

Inspect a possible race around a shared sensor buffer and an asynchronous subscriber.

sensors/imu_driver.cpp 
void readImuData(void* arg) {
    ImuSensor* sensor = static_cast<ImuSensor*>(arg);
    while(1) {
        if (sensor->isDataReady()) {
            uint8_t buffer[64];
            sensor->readRegisters(buffer);
            
            xSemaphoreTake(sensor->mutex, portMAX_DELAY);
            memcpy(sensor->sharedBuffer, buffer, 64);
            xSemaphoreGive(sensor->mutex);
            
            sensor->notifySubscribers();
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}
@arcostasi Code note

Potential race: notifySubscribers() runs after the mutex is released. If a subscriber reads sharedBuffer asynchronously, another task could overwrite it before the read completes.

Safer pattern: Pass an immutable snapshot or queue item to subscribers. Avoid holding a mutex while invoking callbacks unless their behavior is bounded and explicitly safe.
